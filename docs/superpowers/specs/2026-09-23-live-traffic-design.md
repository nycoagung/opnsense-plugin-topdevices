# Live traffic for TopDevices: design

- **Status:** draft for review
- **Date:** 2026-09-23
- **Branch:** `live-traffic`
- **Baseline:** release `0.0.1` (`0dac056`), the widget as deployed on the reference
  firewall (OPNsense 26.7.4, FreeBSD 15.1, Python 3.13).

## 1. Goal

Add a **Live** view to the existing TopDevices widget. It shows each device's current
download and upload rate, updated every second, together with the WAN link's current
rate. It must be accurate, cheap on the firewall and self-cleaning, with nothing
hardcoded.

Success criteria, each checked on the firewall before merge (§11):

- Per-device internet rates, plus the firewall's own traffic, reconcile with the WAN
  kernel counters (net of Ethernet headers) to within ±2% over 60 s at > 1 Mb/s.
- A sampler uses no more than 10% of one core at worst, because it throttles itself.
  Typical use is expected to be about 3% or less.
- No sampler outlives its viewer by more than about 2 s, and none survives a configd
  restart.
- Every existing NetFlow view behaves exactly as in 0.0.1.

## 2. Non-goals

- **IPv6 attribution.** IPv6 connections are counted and reported, but not attributed.
  The reference install has no routable IPv6 to verify against.
- **Per-connection domain names.** The pf state table carries no SNI (the site's
  hostname from the TLS handshake), as the README already explains for NetFlow.
- **Stored live history.** Live is a view of now; the NetFlow ranges remain the
  history.
- **One sampler shared between viewers.** Each open dashboard gets its own, as core's
  Traffic Graph does. See §5.6 for why this is affordable.
- **Testing with non-root users.** The ACL entry is written but only root exists to
  test with.

## 3. Why the pf state table

All of the following was measured on the reference firewall on 2026-09-23. The ground
truth was always the kernel interface counters.

| Source | Result |
|---|---|
| `GET /api/diagnostics/traffic/top/<ifs>` (iftop; core's "Top talkers") | Reported **32%, 35%, 38% and 68%** of a steady 3.0 Mb/s load in four runs. Every call takes **10.5 s** if any listed interface is idle, and 2.5–3.6 s otherwise. Its per-peer detail has one direction only, so internet-only upload is impossible. VLAN devices also appear as one-direction phantom rows on the parent interface. |
| Deltas of `POST /api/diagnostics/firewall/query_states` | Reconciled to **100.0% of WAN rx and 100.3% of WAN tx** over 10.7 s. That counts device traffic, the firewall's own traffic, and 14 bytes of Ethernet header per packet. Without swapping port-forward directions (§5.4), upload only reached 91%. However, each poll takes **0.53–0.64 s** and returns ~420 KB, which the web server does not compress. That is too heavy to poll every second from the browser. |
| `query_pf_top` | configd caches it for 30 s (`cache_ttl:30`), and it reports one merged byte count with no direction. |
| Raw `pfctl -vvs state` | **7 ms of CPU for 1,008 states.** Almost all of the stock endpoint's cost is its parsing and PHP overhead, not the state dump itself. |

Conclusion: read the state table on the firewall, in a lean long-running process, and
send the browser only the per-device result.

## 5. Sampler (`live.py`)

Python 3.13 (the firewall's version), standard library only. The logic lives in pure
functions (parse, delta, classify, aggregate, throttle, drift) so tests need no
OPNsense. A thin loop wires them to `pfctl`, `ifinfo`, the clock and stdout.

### 5.1 Arguments

It takes one argument: the interval in whole seconds, from 1 to 10. Anything else
produces a single error event, then exit status 1. configd already single-quotes
parameters (`BaseAction._cmd_builder`); this validation is defence in depth.

### 5.2 Networks and addresses

These are derived from `ifconfig -a` inet lines at start-up and again every 60 s, so a
DHCP change on the WAN is picked up.

- **Local networks:** the subnets (address and netmask) of every interface address that
  falls inside RFC 1918 (`10/8`, `172.16/12`, `192.168/16`).
- **Upstream interfaces:** those with an IPv4 address that is not RFC 1918, not
  loopback and not link-local. This is the widget's existing rule, which also treats
  CGNAT `100.64/10` as upstream.
- **Firewall addresses:** every inet address on the firewall. These are never shown
  as devices.
- **Never use `ipaddress.is_private`.** It returns `True` for the documentation ranges
  (for example `192.0.2.1`, checked on Python 3.14), and its semantics have changed
  between Python versions. Always use the explicit RFC 1918 list.

### 5.3 One sample

1. **Read the table.** Run `pfctl -vvs state` and parse each state into `id`,
   `direction`, `src`, `dst`, `nat` (optional), `dst_port`, `bytes = (fwd, rev)` and
   `age`. The field semantics follow core's `lib/states.py::query_states`. The parser
   counts lines it cannot parse (`unparsed`) instead of guessing. IPv6 states are parsed
   and differenced like IPv4 ones, but are never attributed. They are counted in
   `v6_skipped`, and their bytes feed only the drift check (§5.8).
2. **Read the WAN counters.** Run `ifinfo <dev>` for each upstream interface and take
   bytes and packets, received and transmitted.
3. **Diff against the previous sample**, keyed by state `id`:
   - a state seen before contributes `bytes − previous bytes`;
   - a new state contributes all of its bytes if `age ≤ dt + 1`;
   - a negative difference means the id was reused, so it is treated as a new state;
   - a vanished state contributes nothing, losing its last partial interval.
4. **Classify** each difference (§5.4) and **aggregate** per device (§5.5).
5. **Emit** one event (§5.7), flush, and sleep until the next tick (§5.6).

The previous snapshot is rebuilt from scratch every sample, so memory is bounded by
the size of the state table.

### 5.4 Crediting rules

`b0` is initiator→responder and `b1` is the reverse. Both were verified against
kernel counters: `b1` is download for outbound NAT.

| Kind | Condition | Scope | Device | down | up | peer |
|---|---|---|---|---|---|---|
| Outbound NAT | `dir=out`, `nat` local and not a firewall address, `src` not local | internet | `nat` | b1 | b0 | `dst` |
| Port-forward | `dir=in`, `nat` not local, `dst` local and not a firewall address, `src` not local | internet | `dst` | b0 | b1 | `src` |
| Ingress, local initiator | `dir=in`, `src` local and not a firewall address | all | `src` | b1 | b0 | `dst` |
| Ingress, local responder | `dir=in`, `dst` local and not a firewall address | all | `dst` | b0 | b1 | `src` |
| Firewall's own | `nat` is a firewall address; or no `nat` and `src` (out) or `dst` (in) is a firewall upstream address | drift check only | none | | | |
| IPv6 | any | counted in `v6_skipped`, bytes to the drift check | none | | | |

Consequences, each one a test case:

- **Internet classification needs no WAN address.** It only asks "did NAT translate
  between local and non-local?", so a DHCP change on the WAN cannot break it.
- **The DNS redirect to a local resolver is not internet.** Its source is local, so it
  fails the port-forward rule.
- **Every routed flow has an `in` state and an `out` state with identical counters.**
  Counting "all" only on `in` states counts each flow once.
- **Cross-VLAN traffic** credits both devices under "all" and neither under "internet".
- **WireGuard clients** are NAT'd like everyone else, so a `10.x` tunnel address
  becomes a device. NetFlow cannot attribute this traffic at all (README).

### 5.5 Per-device aggregate

Rates are in bits per second: bytes × 8 / `dt`. Only devices with traffic in the
interval are included.

- `all: [down, up]` and `inet: [down, up]`.
- `peers`: the union of the top 10 peers by all traffic and the top 10 internet peers,
  as `[ip, down, up, inet]`. `inet` is 1 when the peer is not in a local network; for
  such peers both scopes see the same connections, so the numbers agree. Taking the
  union keeps internet peers visible for a device whose local traffic dominates, such
  as an NVR.
- `ports`: `{"all": [[port, down, up], …], "inet": […]}`, the top 5 of each. The port
  is the responder's port (`dst_port`).

### 5.6 Timing, cost budget, lifetime

- **Clock.** Ticks follow the monotonic clock. `dt` is measured on the firewall and
  never guessed by the browser.
- **Cost.** `cost_ms` for each sample is the sampler's own CPU
  (`time.process_time`) plus its children's (`resource.getrusage(RUSAGE_CHILDREN)`),
  so `pfctl` and `ifinfo` are included.
- **Self-throttle.** An EMA of the cost over 5 samples decides the effective interval:
  `max(requested, cost_ema / 0.10)`. That keeps the sampler within 10% of one core. The
  event reports `effective` and `throttled`, and the interval returns to the requested
  value once cost falls.
- **Keepalive.** The web relay ends a stream that is silent for longer than
  `requested + 4 s` (§6.2). While throttled, the sampler therefore writes a `: keepalive`
  comment line every requested interval.
- **Hourly recycle.** The sampler exits cleanly after 3,600 s. Its first output line is
  `retry: 1000`, so the browser reconnects about 1 s later and a fresh process takes
  over. This bounds anything slow-growing that the soak test might miss.
- **Exit on broken pipe.** A `BrokenPipeError` on stdout ends the process, for example
  when configd restarts underneath it. It can never outlive its reader.
- **No stderr in the loop.** configd only drains stderr after the process exits, so a
  full stderr pipe would block the sampler. Errors go into the event's `error` field.
- **Expected cost.** About 1–3% of one core per viewer, from the 7 ms dump plus parsing.
  This is to be measured (§11.4).

### 5.7 Event

The stream carries only numbers and IP addresses. The web relay HTML-escapes every
line for browser clients (`Response::send`, `htmlspecialchars`), and names are joined
in the widget from DHCP data anyway.

```json
{
  "v": "0.1.0", "t": 1790125733.293, "dt": 1.001,
  "interval": 1, "effective": 1, "throttled": false, "cost_ms": 18,
  "states": 1008, "unparsed": 0, "v6_skipped": 0,
  "wan": {"devs": ["em0"], "down": 6100000, "up": 200000},
  "coverage": {"down": 0.99, "up": 1.00, "ok": true},
  "devices": {
    "192.168.1.10": {
      "all": [5656000, 108000], "inet": [5656000, 108000],
      "peers": [["203.0.113.7", 5600000, 100000, 1]],
      "ports": {"all": [[443, 5600000, 100000]], "inet": [[443, 5600000, 100000]]}
    }
  },
  "error": null
}
```

- The first event has `dt: 0` and no devices, because it is only the baseline.
- `coverage` is `null` until the drift check has enough traffic to judge (§5.8).
- `v` is the sampler version. It also lets verification confirm the deployed backend
  without SSH.

### 5.8 Drift check

This guards against silent breakage after a firmware update. Over a sliding 60 s
window, for each direction:

```
attributed = Σ internet device bytes + Σ firewall-own upstream bytes + Σ v6_skipped bytes
expected   = Σ WAN interface bytes − packets × 14      (Ethernet interfaces only)
coverage   = attributed / expected
```

- `ok` is `false` when either direction leaves `0.90–1.10`. It is only evaluated while
  WAN traffic in the window averages more than 1 Mb/s; below that, keepalives and
  blocked scans dominate and the ratio means nothing.
- **Header size.** `ifinfo` reports a `header length` of 18 on `em0`, which is the
  VLAN-capable maximum, but the measured reconciliation needed 14 bytes per packet. So
  the check uses 14 for Ethernet and 0 otherwise, and the band absorbs the rest.
- **Why a full band rather than ±2%.** Blocked inbound packets never create states, so
  a small download shortfall is normal.

### 5.9 Errors

- A `pfctl` or `ifinfo` failure produces an event carrying `error` and no devices. The
  stream continues and recovers on the next good sample.
- An unparseable table shows up as a high `unparsed` count and a failed drift check,
  never as silently wrong numbers.

## 6. API, configd, ACL

### 6.1 configd action (generated by `install.sh`)

```
[live]
command:/usr/local/opnsense/scripts/topdevices/live.py
parameters:%s
type:stream_output
message:TopDevices live stream (%s s)
```

`message` logs one line per stream start. That is traceable, and costs a few MB a year
at 365-day retention.

### 6.2 Controller

`OPNsense\TopDevices\Api\LiveController::streamAction($interval = 1)`:

- It rejects anything but an integer from 1 to 10.
- It calls `$this->configdStream('topdevices live', [$interval],
  ['Content-Type: text/event-stream', 'Cache-Control: no-cache'], $interval + 4)`.
- **The relay timeout.** `configdStream`'s poll timeout becomes the relay's
  `stream_set_timeout`. In `Response::send`, a stream read that times out ends the
  response, which is why the sampler guarantees a line at least every requested
  interval.

### 6.3 ACL and widget metadata

```xml
<acl>
    <page-dashboard-topdevices-live>
        <name>Dashboard: Top Devices live traffic</name>
        <patterns>
            <pattern>api/topdevices/live/*</pattern>
        </patterns>
    </page-dashboard-topdevices-live>
</acl>
```

`Metadata/TopDevices.xml` gains `<endpoint>/api/topdevices/live/*</endpoint>`.

## 7. Widget

### 7.1 Behaviour

- **Range dropdown.** **Live** is the first entry and can be chosen as the default
  range. The new widget option *Live update interval* offers 1 s (default), 2 s and
  5 s.
- **Table.** Down, Up and Total show bits per second (e.g. `5.6 Mb/s`). Sort, network
  filter, search, row count and the All / Internet only scope all apply. Changing scope
  is instant, because every event carries both scopes.
- **Summary line.** It reads
  `Live · WAN ↓ 6.1 Mb/s ↑ 0.2 Mb/s (via em0) · internet only · 1 s`. It adds
  `throttled to N s` when the sampler has slowed down, and a warning when `coverage.ok`
  is `false`.
- **Readability.**
  - Rows and chart show a 3-second time-weighted average (`Σ rate·dt / Σ dt`), and the
    WAN figure shows the last interval alone.
  - A device that goes quiet stays listed at 0 for 10 s before it drops off.
  - Row order freezes while the pointer is over the table; values keep updating.
- **Chart.** It is updated in place (`chart.update('none')`) rather than destroyed and
  rebuilt each second.
- **Device panel.** It shows live down/up, peers and ports, with the same 3-second
  averaging, and reverse DNS through the existing cache and bounded concurrency. The
  10/50/100 selector is hidden, because the sampler sends a fixed top 10.
- **NetFlow tick and refresh button.** The NetFlow tick is skipped while Live is shown,
  and the header refresh button restarts the stream instead.

### 7.2 States

`off → connecting → measuring → live ⇄ reconnecting → unavailable`

- **measuring:** until the second event arrives, one interval.
- **reconnecting:** no event for `max(6 s, 3 × effective)`, or the hourly recycle. The
  last values stay on screen meanwhile.
- **unavailable:** no event for `max(20 s, 6 × effective)`. The widget shows "Live data
  unavailable" with a Retry link, which resets `eventSourceRetryCount` and reopens the
  stream. This covers a firmware upgrade having removed the backend.
- **Why the timeouts scale.** `effective` comes from the latest event. EventSource
  never surfaces the sampler's `: keepalive` comment lines, so fixed timeouts would
  report a throttled or 5 s stream as down.

### 7.3 Lifecycle traps (from `BaseWidget.js`)

- **Opening the stream.** Open it through `this.openEventSource()`. The base class
  closes it when the tab is hidden and reopens it when the tab is visible again.
- **Leaving Live.** Leaving Live must set `this.eventSourceUrl = null` after closing
  the stream. `onVisibilityChanged` reopens any remembered URL, and closing does not
  clear it.
- **Closing the widget.** `onWidgetClose()` must call `super.onWidgetClose()`. The 0.0.1
  override does not, and the base implementation is what closes the stream.
- **Connection failures.** `openEventSource` gives up silently after 3 failed connects,
  hence the widget's own watchdog in §7.2.

### 7.4 Testable core

`mergeLive(view, event, nowMs)` is a pure function, exported alongside the default
class. It handles the averaging, the idle-device linger and dropping stale devices. A
Node test loads the module with a stubbed global `BaseWidget`.

## 8. Installer

- **File list.** It grows from 3 files to 6: `live.py` is installed 0755 (`*.py`,
  alongside `*.sh`), and PHP and XML files 0644. The whole set is still checked present
  before anything is written, and is staged as `.tdnew` and then moved into place.
- **Action file.** The generated action file gains `[live]` (§6.1).
- **configd restart.** It happens only when the action file changed, and is detached
  and delayed:
  `/usr/sbin/daemon -f /bin/sh -c 'sleep 1; /usr/local/etc/rc.d/configd restart'`.
  - Upstream's own plugin post-install scripts restart configd synchronously
    (`Templates/actions.d` in opnsense/plugins).
  - `configd_stop` signals only the pid in its pidfile, then `kill -9`s processes whose
    `ps -ex` line matches `configd.py`. The installer should therefore survive even a
    synchronous restart; §11.6 verifies it.
  - Detaching is so that a `configctl topdevices install` call gets its reply rather
    than a dropped connection.
- **ACL cache.** The installer clears it through core's own API, rather than by path:
  `php -r 'require "/usr/local/opnsense/mvc/script/load_phalcon.php"; (new OPNsense\Core\ACL())->invalidateCache();'`.
  It prints whether that succeeded. The cache is
  `/var/lib/php/tmp/opnsense_acl_cache.json` with a one-hour TTL. Clearing it makes the
  new privilege appear immediately.
- **Upgrade from 0.0.1.** The 0.0.1 installer has only three files in its list. Run
  from `configctl` or cron, it installs the new widget and the new `install.sh`, but not
  the backend, until its next run. The first upgrade must therefore use the bootstrap
  command, which runs the new installer from the downloaded tree (§12). The README
  documents this.

## 9. Security

- **Access.** The endpoint sits behind OPNsense authentication and its own ACL
  privilege, and today only root has it. It exposes per-device peers, which is
  equivalent to Diagnostics → States, and should be granted as carefully.
- **Input.** The interval is validated in PHP and in Python, and configd quotes it.
- **Output.** It contains only numbers and IPv4 addresses, so the relay's HTML
  escaping cannot corrupt it. Names are inserted through the widget's existing `_esc`.
- **Firewall state.** Nothing reads or changes firewall configuration. The sampler
  runs two read-only commands, and nothing is written to disk each second.

## 10. Tests (local, before anything reaches the firewall)

- **`tests/test_live.py`** uses stdlib `unittest` and is table-driven over synthetic
  `pfctl -vvs state` text. It covers:
  - the parser, including NAT, port-forward, IPv6 and unrecognised lines;
  - every row of §5.4, including the DNS redirect, cross-VLAN, firewall-own and
    WireGuard cases;
  - the differencing cases (seen before, new, stale-new, vanished, id reuse);
  - peer and port ranking, including the union rule;
  - the throttle and drift arithmetic;
  - that no output contains `<`, `>` or `&`.
- **Fixture addresses.** Internet addresses in fixtures come from the RFC 5737
  documentation ranges. No address from the reference network enters the public repo.
- **Differential test.** Core's own `lib/states.py` parser from 26.7.4 is run on the
  same fixture text, with `subprocess.run` stubbed, and must agree with ours on every
  field we use.
- **Mutation check.** The suite must fail against deliberately broken copies: the
  port-forward swap removed, the local-source check on the port-forward rule removed,
  `in`-only counting replaced by counting both states, and `is_private` used instead of
  RFC 1918.
- **`tests/live_view.test.mjs`** (Node) tests `mergeLive`: the averaging with uneven
  `dt`, the linger and expiry, and switching scope.
- **Python compatibility.** Tests run on Python 3.14 locally. The code must also run on
  3.13, so no syntax newer than 3.13 is allowed.

## 11. Verification on the firewall (before merge)

The user installs the branch. Checks run through the API unless marked (user).

1. **Deployed files.** The widget JS and metadata match the branch by sha256 over
   HTTPS, and each event's `v` matches the sampler version.
2. **Accuracy.** Over 60 consecutive events, internet devices plus firewall-own traffic
   match the WAN counter (net of headers) within ±2%. IoT camera uploads under "all"
   match the `vlan01` rx counter.
3. **(user) Real devices.**
   - A speed test on one device shows that device at the speed-test rate.
   - A device behind a shaper pipe tops out at the pipe's limit (25 Mbit/s on the
     reference install).
   - A phone connected over WireGuard appears with its tunnel address.
4. **Cost.** Record the median and maximum `cost_ms` over a minute, and the sampler's
   CPU in `diagnostics/activity`.
5. **Lifecycle.**
   - Hidden tab: the process is gone within 2 s. Visible again: it is back.
   - Switching to 24 h: the process is gone, and stays gone through a hide/show cycle.
   - Widget removed: gone.
   - (user) `service configd restart`: gone.
6. **Upgrade path under configd.** (user) Append a comment line to the installed action
   file so the installer sees a change, then run `configctl topdevices install`. It must
   print its result, and configd must be back within 5 s with `topdevices live`
   registered. This is the path a future release's weekly install would take; an
   unchanged action file skips the restart and would test nothing.
7. **Soak.** The dashboard stays open for 30 minutes and across one hourly recycle. The
   sampler's resident memory stays flat and the view shows no gaps longer than the
   reconnect.
8. **NetFlow regression checklist.** Every range, both scopes, filters, sort, row
   counts, detail panel, both charts, custom range and refresh all behave as in 0.0.1.
9. **ACL.** (user) Straight after install, *Dashboard: Top Devices live traffic*
   appears under System → Access → Groups → privileges, without waiting for the
   one-hour cache to expire.

## 12. Rollout and rollback

1. **Install the branch by hand from an SSH shell**, not through `configctl` or cron:
   ```
   fetch -qo /tmp/td.tgz https://codeload.github.com/nycoagung/opnsense-plugin-topdevices/tar.gz/refs/heads/live-traffic && \
     rm -rf /tmp/tdx && mkdir -p /tmp/tdx && tar -xzf /tmp/td.tgz -C /tmp/tdx && \
     sh /tmp/tdx/opnsense-plugin-topdevices-live-traffic/install.sh
   ```
2. **Health check straight away.**
   - configd answers (any configd-backed endpoint responds).
   - The stream delivers events.
   - Parental Control's per-minute sync has run since the restart.
   - The dashboard loads.
3. **Run §11.** Finish before Sunday 05:00, or pause the weekly TopDevices job,
   because that job reinstalls `main`.
4. **Merge only after §11 passes.** The branch carries `0.1.0` from the start, in
   `Makefile`, a `pkg-descr` changelog entry and the sampler's `v`, so §11.1 can check
   it. Merge to `main`, tag `0.1.0`, publish the GitHub release, and update the README
   with what was verified. The firewall already runs the new installer by then, so
   weekly runs do not restart configd again.
5. **Rollback.** Run the `0.0.1` bootstrap from the release notes, from an SSH shell.
   It rewrites the action file without `[live]` and restarts configd. It leaves
   `live.py`, `LiveController.php` and `ACL.xml` behind; they are inert, and the README
   lists them for removal.

## 13. Risks

| Risk | Mitigation |
|---|---|
| configd fails to come back after the one restart | Manual first install with an immediate health check (§12). Detached restart. Recovery is `service configd restart`. |
| CPU cost when the state table grows (P2P, scans) | Self-throttle to 10% of one core (§5.6). |
| Silent misattribution after a firmware update changes `pfctl` output | `unparsed` count plus the drift check (§5.8), surfaced in the widget. |
| Bugs, including NetFlow regressions in the shared JS file | Tests first, differential and mutation checks, review before install, branch install, the §11.8 checklist, and rollback. |
| Unattended rollout by the weekly job | Merge only after the manual install is verified (§12). |
| Slow-growing process state or half-open connections | Snapshot rebuilt each sample, the soak test, and the hourly recycle. |
| Exposure of per-device peers | ACL privilege, root-only today, validated input. |

## 14. To confirm during implementation

These are not blocking the design; each has a planned check.

- `new OPNsense\Core\ACL()` works from the CLI without a session (§11.9).
- `pfctl -vvs state` variants on 26.7, such as `route-to`, `rtable` or several flag
  words, are handled or counted as `unparsed` (differential test and §11.2).
- A throttled sampler's keepalive keeps the relay open at the largest effective
  interval (a unit test, plus an induced slow sample on the firewall).
